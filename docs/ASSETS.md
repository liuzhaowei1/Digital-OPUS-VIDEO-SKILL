# 画面素材：代码画 / 生图 / 用户照片

片子里的角色、场景、道具从哪来，是和技术栈并列的决策，写进方案书「技术选型」由用户拍板。生图是**出静态素材**，动起来仍靠代码（Remotion / 内置引擎），不是视频生成模型（不在本 skill 工具箱内）。

## 三种来源怎么选

| 来源 | 适合 | 代价 | 实例 |
|---|---|---|---|
| **代码画**（SVG 部件树 / 着色器） | 抽象、图解、排版；角色要关节能动、绝对一致 | 零费用；角色偏扁平、图标感，"可爱"有限 | Remotion 模板里的 `narration/`（`Chars.tsx` 角色与道具，示例 `NarrationDemo`） |
| **生图·整幅场景图** | 插画质感优先、角色不需要动，生动感交给镜头推拉和叠加特效 | 每镜 1 张 | 一段 3 镜的旁白样片约 $0.035 |
| **生图·角色抠图 + 无人场景图** | 同一角色跨很多镜头、要位移/弹跳/破框登场 | 角色设定图 + 场景图各若干张；抠图边缘要检查 | 一部生日视频：8 个 Q 版角色 + 约 30 张场景 |
| **用户照片 → 生图** | 个人向片子（生日、纪念）：真人转 Q 版、真实去过的地方转插画 | 同上 | 生日视频：寿星照片 → Q 版角色；去过的地方的照片 → 黏土风场景 |

用户照片原图默认不进画面（只做生图参考），要放进画面先问。

## 工具
- `scripts/gen_image.sh <prompt文件> <输出png> [尺寸=1536x1024] [质量=medium] [参考图...]`
  - 不给参考图 → `/images/generations`；给参考图 → `/images/edits`（可给多张）
  - 走 OpenAI 图像接口，模型默认 gpt-image-2.5-flare（`OPUS_IMAGE_MODEL` 可改）；key 读环境变量 `OPENAI_API_KEY`（或 `OPUS_IMAGE_KEY_FILE` 指向的文件）；撞限流自动重试；打印的费用是按脚本单价估算，不是账单
  - 实测单价（medium）：1536×1024 文生图约 $0.012；edits 出 Q 版角色约 $0.022、出场景约 $0.02
- `scripts/cutout.py <png...> --out-dir <目录> [--tol 9]`（用 `$OPUS_HOME/_venv/bin/python`）：从四边泛洪去掉纯色底，输出裁边的 RGBA PNG。只去和边框连通的底色，角色身上相近的颜色不会被挖空

## 角色一致性
- **先定设定图，再以设定图为参考出其余所有图**：设定图过用户审（像不像、发型、服装），之后每张都用 edits 带上设定图，提示词再重复一遍外貌要点
- 只用文字描述也能在少量图里保持一致（A 方案 3 张实测一致），但镜头一多会跑偏，多镜头片子一律走 edits
- 要抠图的角色：提示词写"plain solid <颜色> background, no other people, no text"；底色选接近成片背景的颜色，深色背景上会看到一圈细浅色描边
- 场景图提示词写"NO people, no text"，角色另外叠上去；叠加层不能挡住画面主体
- 画面里的文字一律由代码叠加，不让生图模型写字

## 个人向片子的经验（生日片）
- 同类元素连续登场（8 个形象），每个要有不同的出场方式和背景，"节奏和画面感太一致了"不行；数量多时宁可减少，每张要停留到看得清
- 整幅图直接铺满画面感觉不好 → 缩小、加相框等外框
- 字体按片子气质选（生日片要"网感重一点、俏皮一点"），先出字样图让用户挑
- 个人向片子的背景优先用用户真实生活元素（去过的地方、宠物），比通用场景打动人
