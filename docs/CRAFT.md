# 工艺与手法库

两部分：**通用工艺**是换任何风格都成立的做法；**手法库**是可以跨类型借用的技法，每条写清适合什么内容、不适合什么、出自哪部片子，按内容挑，不是每部都用。某部片子自己的审美（色板、语气、负面清单）不在这里，在风格库各片 md 里；pdoom 的完整风格圣经原文在 `docs/upstream/TREATMENT.md`（作者与 Claude 共写，5 轮改稿），借 pdoom 风格时通读。

手法库会持续扩充：每拆一部参考片（`docs/REFERENCE.md`），技法对照里用户同意收的手法加一行。现有条目不是全集，内容需要而库里没有的手法，在方案书里提出来。

## 一、通用工艺

### 方案书结构（Step 4 照这个写）
1. **一段话创意**：视频"是什么"（pdoom = "一部关于世界末日的插图论文的图版"）、贯穿线、每个场景的共同语法
2. **语气**：3~4 条，每条带正反例
3. **负面清单**：这部片子不要什么。按本片风格写，不从别的片子照抄（pdoom 的"不要发光粒子、紫青赛博"对暗场辉光风格就不成立）
4. **色板**：每个颜色一个 hex + 角色；哪个能发光；稀有强调色归哪一个瞬间
5. **字体**：每套字体一个"声音"（谁在说话）
6. **文字规则**：歌词或字幕怎么进画面
7. **选用的手法**：从下面手法库挑，每条写一句"为什么适合这条内容"；说不出理由就不用
8. **分场表**：id / 时间窗 / 歌词或内容 / 画面 / 转场 / 实现依赖（已有·需新装·做不到，见 SKILL.md Step 4）；然后每场一段具体描述（发生什么、在哪一拍、镜头怎么动、字怎么进画面）
9. **技术约定**：确定性、卡拍、性能预算

### 分场：先定认知动作，再定画面动作
- 每一镜先问"这句话要观众完成哪个思考动作"，再挑画面动作，不是"这句配一张什么图"。常用对照：剖开 = 看内部；加载/按压/通电 = 看反应；染色 = 指认；移除 = 证明多余；描亮 = 引导视线走一条路径；叠上旧方案 = 比较；夸大变形 = 让看不见的变得看得见；从纸上抬起变成实体 = 从记载到理解（《拓扑优化》）
- 画面真实度按话题定：核心是看得见的物理过程（机械、结构、化学反应）就让实物按物理规律演；核心是抽象关系（AI、数学、情绪）就走图形和隐喻；两样都有的按知识种类分舞台

### 运动
- 缓动要有意图：每个动作选一种缓动并说得出为什么（`outExpo` 停住再猛地到位、弹簧带回弹、线性用于匀速机械感）；没有理由的匀速漂浮最容易显得廉价
- 场景内部也可以有子切换：重新构图、推近、甩镜
- 动静比按内容定：要观众读的字，读完前别散

### 排版
- 每套字体一个声音。中文常用：思源黑体 = 主声音，思源宋体 = 引文与郑重时刻，Plex Mono = 机器（标签、HUD、读数）
- 字距逐字用字体自己的 kerning（`layout()`/`glyphX()`）；分段绘制同一个词不能丢字距
- 印刷标点（’ “ ” … – — × −），机器声音保留打字机引号
- 正文小字保持锐利，发光只给标题和信号色
- 不用字体系统以外的字形；缺的个别符号自己画。成套专门排版（数学公式、乐谱、化学结构式）不手拼，分场表标「需新装」（如 KaTeX），随方案拍板
- 文字留在标题安全区（距边 ≥96 px，竖屏按比例）

### 文字与声音同步（有歌或旁白时）
- 每句可读，逐词同步：词在开始唱/说时出现或点亮，唱完时完成；可以提前约 0.4 秒淡显，**高亮绝不抢跑**
- 默认：已唱部分实色，未唱部分 30~40% 透明
- 切点吸附：切在"歌词行第一个词之前最近的拍"或"行尾最近的小节线"；旁白片切在句子边界
- 动作触发查表：`audio.hit('kick', t)` 做冲击、`audio.env('vocal', t)` 驱动呼吸、`f.beatPhase` 做每拍脉冲；数据先由 `analysis/` 算好

## 二、手法库

出处写片名的，原片链接见 `docs/REFERENCES.md`；自己拆过的片子，细节读风格库 `$OPUS_LIBRARY/<片名>/` 里 md 的「风格分析」「复用指南」。

### 贯穿线：让全片成为一条片子，而不是一组页面
| 手法 | 做法 | 适合 | 不适合 | 出处 |
|---|---|---|---|---|
| **贯穿物体** | 少数几个主角物体从头活到尾，靠移位、缩放、变形、换身份承接下一句，不整屏换页；可以是一个母题接力变身（点 → 笔 → 曲线 → 导火索），也可以是几个主体轮流居中、退到角落当标签、结尾集体回收 | 信息条目不多、能找到具体物件代表每个概念的内容：资讯速览、科普、概念短片、MV | 场景本来就要跟着话跳的内容（口播·插画叙事）；每段刻意换画风的片子要改成"换画风但母题不断" | 《AGI概念MV》（母题接力）、《时·RELATIVITY》（钟）、《DevDay速览·三模型同题》Opus 栏（点阵球、太阳、行星）；极简版：一颗圆点换身份讲完品牌（《popwise·扁平矢量》），一个形状连续变形讲完一天（《morphe·形变动画》） |
| **数值脊柱** | 一个递增的数藏进每个场景的道具（参数行、表单、仪表），高潮放大整屏，最后涨破定义域（→ ∞ → NaN）。引擎 `Readout` + `project.json.readout` | 有"量在累积"的主题：风险、时间、规模 | 没有天然数量的情感或叙事内容 | 《AGI概念MV》、《在我窗下》（计数器）；变体：起点是「无法量化」的模糊需求，先把它定义成一个数，最后涨破到 NaN 把评分交还观众（《足够震撼》）；高潮段可做成数量级阶梯：沿对数刻度尺一级级往上跳，每级配一句一本正经的冷注释（≈π 无理、42 答案（问题待定）、googol、双精度浮点数上限），直到超出可表示范围——冷注释不适合严肃数据，会被当真（《足够震撼》） |
| **首尾回环** | 结尾回到开场的画面、界面或台词；变体：开头给结果结尾补"已完成"、意思反转、全片倒带快闪再回原点 | 有起点和归宿的内容，几乎都可用 | 刻意开放式结尾 | 《我从未见过太阳》、《Claude Dreaming》、《从现在看过去·AI简史》、《时·RELATIVITY》 |
| **具名光标当主角** | 一个带名牌的箭头光标（固定一种醒目色，如橙色"Sarah"）代表用户，全片由它点、拖、选，替代真人出镜，让每个操作有主语；痛点段它在抱怨，演示段它把活交给 AI | UI 演示、产品宣传、软件教程 | 没有交互界面的内容 | 《ClickUp AI·产品宣传》 |
| **语义色** | 一个颜色绑定一个意思后贯穿全片；变体：唯一暖色 = 主角、状态色升级、每段一个主色 | 段落分明或有情绪升级的片子 | 每段换画风且色板本身就是变化点的片子 | 《我从未见过太阳》、《在我窗下》、《如果聊天窗口就是她的整个世界》、《DevDay速览·三模型同题》Opus 栏、《拓扑优化》（青 = 拉、红 = 压，从梁截面用到桁架杆件）；变体：整屏换色表示状态或时间——同一界面青 → 橙表示进入锁定告警（《隼眼-9·赛博朋克HUD》），同一场景只换调色板从正午走到黄昏和夜晚，省场景又有时间流逝（《PIXEL QUEST·像素风》，适合像素、复古游戏题材，不适合写实） |
| **实物舞台** | 按知识种类分几个固定舞台（史料在木桌、物理现象在工地、理论在黑板），舞台内镜头连续漫游、靠物体自己变化推进，舞台之间黑场切 | 讲一条论证链、知识种类混合的科普 | 资讯速览（条目跳得快，搭舞台不值）、≤1 分钟短片 | 《拓扑优化》 |
| **超大画布 + 相机运镜** | 所有图表放在一张数倍于屏幕的平面画布上，靠镜头推拉平移从一张讲到下一张，观众始终知道自己在哪；同一批数据块从一个图表飞成下一个图表（周期表 → 分类柱 → 地图），数据身份不断。实物舞台的平面单舞台版 | 有多个相关图表、同一批对象做多维统计的数据科普 | 章节之间互不相关的内容 | 《一部手机里的元素·贴纸风科普》 |

### 把概念变成画面
| 手法 | 做法 | 适合 | 不适合 | 出处 |
|---|---|---|---|---|
| **视觉双关** | 抽象概念找一个具体物件的变形（急左转 = 路线图急转；安全护栏 = 安全框被冲破） | 观点、隐喻多的内容 | 要求字面准确的操作教程 | 《AGI概念MV》 |
| **可计算对象** | 一句话对应一个真实可算的公式、数据结构或仪表 | 技术、科学题材 | 情感、生活题材 | 《被定义的我》、《如果聊天窗口就是她的整个世界》 |
| **数字做成可比的形状** | 比例画成格子（5 格对 1 格）、大数换算成可感知的量（每秒数一个要数 5,545 年） | 有数据的资讯、科普 | 无数据内容 | 《DevDay速览·三模型同题》、《从现在看过去·AI简史》、《时·RELATIVITY》；变体：把前面出现过的旧方案叠到新方案上比体积（《拓扑优化》） |
| **抽象阶梯** | 同一对象在"实物 → 实物上标注 → 纸上图示 → 线框 → 实体部件"之间来回变身，一次只升降一级，抽象始终有可见的落脚点 | 理论要落到实物的理工科普 | 观点、情绪类内容 | 《拓扑优化》 |
| **史料道具化** | 没有动态素材的人物和文献做成桌面道具（肖像照、手稿、期刊原页 + 荧光笔），镜头在桌上漫游 | 有历史渊源的知识、发明史 | 无史料的话题；图源须公有领域 | 《拓扑优化》 |
| **材料即主题** | 世界的材质等于主题（讲"AI 只知道文字"，万物由文字构成） | 有单一核心隐喻的短片 | 多主题拼盘 | 《我从未见过太阳》 |
| **UI 讲故事** | 进度条文件名、属性面板、界面自己坏掉（缺号、乱码）来表达心理或状态 | AI、软件题材 | 与屏幕无关的题材 | 《Claude Dreaming》、《如果聊天窗口就是她的整个世界》、《在我窗下》 |
| **逐句一镜** | 每句旁白演成一个场景（角色、动作、情绪符号），动作卡在具体的字上 | 口播·插画叙事：讲人、关系、情绪 | 讲解类、资讯类（会碎成幻灯片，贯穿物体更好） | 情感口播测试片（模板见 `remotion/src/compositions/narration/`） |
| **一个主体 × N 种媒介** | 同一瞬间用几十种媒介重画 | ≤1 分钟的概念短片 | 信息量大的内容 | 《同一朵蘑菇云》 |
| **立规矩 + 反例盖章** | 开工前把风格规范做成一份纸面文件，禁用的东西贴出真样张（霓虹字、镜头光晕、廉价粒子、被淘汰的色卡），逐个打叉、盖「禁止」章，只留下选中的那一个 | 讲审美取舍、设计决策、品牌规范 | 情绪片、叙事片 | 《足够震撼》 |

### 结构骨架
| 手法 | 做法 | 适合 | 不适合 | 出处 |
|---|---|---|---|---|
| **目录 → 展开 → 回收** | 先列 N 个要点，逐个展开，结尾用 N 个小图标收回 | 资讯速览、清单式讲解 | 叙事、MV | 《DevDay速览·三模型同题》 |
| **编号图版** | FIG. 01–N 把片子做成图录 | 科普长片 | 叙事 | 《时·RELATIVITY》 |
| **固定骨架只换中栏** | HUD/版式不动，只换中间内容；成本低、统一感强 | MV·图解、口播·讲解 | 要求空间运动感的片子 | 《如果聊天窗口就是她的整个世界》 |
| **同版式换底色连播** | 一组并列条目（步骤、特性）用同一版式（大编号 + 小标题 + 巨大关键词 + 小字正文），每条只换一种饱和底色和文字，0.5~1 秒一张快速连播，观众靠颜色区分条目；换字时可加字符乱码入场 | 3~6 个并列项的快速列举 | 条目正文要人读完的内容（小字一闪而过只当质感） | 《ClickUp AI·产品宣传》 |
| **每段换画风，锁色板字体颗粒** | 变化多而不散 | 歌曲分段明显的 MV | 短资讯（显得乱） | 《AGI概念MV》 |
| **模板化重复 + 逐次升级** | 同一个钩子出现多次：干净 → 加重 → 反而变安静诡异 → 最满 | 有副歌的 MV | 无重复结构的内容 | 《AGI概念MV》 |
| **朴素方案逐级失败** | 先给最朴素的方案，亲眼演示它哪里不够，改进一步再演示不够，直到观众自己想要答案（实心梁 → 工字梁 → 仍浪费 → 理想结构？） | 讲"东西怎么演进来的"：发明史、工程原理、算法改进 | 无演进关系的清单式内容 | 《拓扑优化》 |
| **痛点 → What if → 演示 → 标语** | 四拍：先用一串界面和抱怨讲现状多累 → 一句全片唯一的问句转折（"What if all of that happened automatically?"）→ 产品一步步替人完成 → 两拍标语（"You bring the idea… / AI handles the execution."）收 logo；30 秒~1 分钟，无旁白 | 工具、产品、功能的短宣传片 | 知识科普、叙事（没有"产品"可演示） | 《ClickUp AI·产品宣传》 |
| **自我解剖** | 片子讲它自己是怎么做出来的：按制作流程分章（需求 → 立规矩 → 配乐 → 渲染 → 自检 → 结账），用前面出现过的镜头当后面讲解的例子，用全片胶片条、接触印样、时间轴回看自己；讲某个机制时，演示用的正是本片自己的那套机制（讲运动模糊就把本片的子帧堆成 3D 薄片，讲卡拍就列出本片切点和鼓点的对照表，Δ 全 0），这一招也可以单独用在技术讲解里 | 工具或能力展示、制作复盘、年终总结 | 内容本身是主角的科普、叙事（会喧宾夺主） | 《足够震撼》 |
| **账单式结算** | 收尾时一台打印机逐行吐出小票（每行一个投入项和数字），旁边的翻页计数器跟着累加，最后撕下小票。引擎有 `ascent-odo.ts`（翻页鼓）、`bureau.ts`（纸面与盖章）可改 | 盘点、成本、战绩类收尾，「零投入」对比 | 没有数字的内容 | 《足够震撼》 |
| **尺度穿越** | 一两次推进/拉出当全片骨架；变体：只在结尾拉一次，揭示前面的一切都发生在主题物里面（整张图表画布原来在手机屏幕里），首尾扣题 | 概念短片、科普；变体适合「X 里有什么」类选题 | 平面信息版式（变体除外） | 《同一朵蘑菇云》；变体《一部手机里的元素·贴纸风科普》 |

### 节奏与文字进画面
| 手法 | 做法 | 适合 | 不适合 | 出处 |
|---|---|---|---|---|
| **情绪曲线 = 速度曲线** | 低谷静止、困境刻意停住，高潮一镜到底连续运动 | 有情绪起伏的叙事、思辨片 | 均匀信息流 | 《Claude Dreaming》、《我从未见过太阳》 |
| **歌词即画面** | 每个场景换一种方式把词做进画面（被写出、骑在曲线上、盖章、[MASK] 遮挡），词不是叠在上面的字幕 | MV | 旁白信息片（字幕要稳定好读） | 《AGI概念MV》、《在我窗下》（一句拆多词、每词一个物体） |
| **逐字点亮字幕** | 已读字实色、未读字灰，下划线随读音推进 | 旁白片 | 无人声 | 《DevDay速览·三模型同题》Opus 栏；无旁白变体：全片唯一的核心问句整句浅色出现，再逐字加深 + 光标，逼观众按语速读（《ClickUp AI·产品宣传》，多句时会拖） |
| **字幕接力** | 多句短证词依次淡入同一位置，代替解说 | 多声部、群像主题 | 单一讲者 | 《我从未见过太阳》 |
| **一拍一事件，拍数定时长** | 先定 BPM 和总拍数，每拍分配一个元素动作（120 BPM × 20 拍 = 10 秒），画面天然卡点；可与网格合成 BGM 共用拍点（docs/AUDIO.md） | 片头、海报生成、强节奏短片 | 旁白片（切点跟句子走） | 《二十拍构成·几何构成包豪斯》 |
| **降帧当风格** | 把动画时间量化到 12 fps 或一拍二，换来手工、定格感；手绘线可再加每帧轻微抖动（线条沸腾） | 手作、拼贴、复古、童趣 | 要流畅科技感的片子 | 《手作·逐帧手绘》、《NOGGIN脑洞季刊·拼贴剪贴》 |
