# 拆参考片：抽帧 → 读图 → 风格分析 md

用户给了一部参考片（本地视频文件，或能下载到本地的链接），要照它的风格做视频时走这里（SKILL.md Step 1）。拆完的分析 md 存进风格库 `$OPUS_LIBRARY`（默认 `$OPUS_HOME/library`），以后说"参考《某某》"就直接读 md，不必再拆一遍。

## 流程

1. **拿到本地文件**。链接先下载到本地（如 `yt-dlp`）；下载不了的请用户自己下好给路径。下载他人作品只用于本地分析，不再发布。
2. **先查一手资料**。简介或片尾给了开源仓库、制作说明的，先读仓库（README、docs、分镜/风格文档），作者公开的风格文档原文另存为 `风格圣经-<原文件名>.md`，分析以它为准、画面核实。比读图反推准得多。
3. **抽帧**：
   ```bash
   $OPUS_HOME/_venv/bin/python scripts/ref_frames.py <视频> --out "$OPUS_LIBRARY/<片名>/frames"
   ```
   产物与参数见脚本头注释。fps 按时长自动选。
4. **读图（不能交给脚本）**：先按顺序读全部拼板 `sheet_NN.jpg`，只在看小字、细节时开 `key/` 原图。每读完一张拼板就记下：画面内容、屏幕文字原文、转场方式、和上一段比变了什么。
5. **回头补漏**：输出里的 `long_segments`（持续 >3 秒的段）去 `tiny/` 回看——暗、低对比的整段常被判成一张；快速蒙太奇里一闪而过的画面，提高 `--fps` 重跑或用 `--extra-sec 秒,秒` 补截。
6. **写分析 md**（模板见下），存 `$OPUS_LIBRARY/<片名>/<片名>.md`。片名用作品原名，没有原名就按内容起一个短名，不用平台上的标题党标题。
7. **类型行**：从 `docs/TYPES.md` 的类型表里选；都不合适时停下问用户要不要新增类型，定了再改那张表，不自建。

查全库：`grep -H "^- 类型" "$OPUS_LIBRARY"/*/*.md`

## 分析 md 模板

```markdown
# <片名>

- 原标题：<平台标题原文>
- 链接：<URL>　作者：<>（转载的写明原作者与原链接）
- 时长：<>　分辨率：<宽×高>
- 拆解：<YYYY-MM-DD>　抽帧 <n> 张
- 类型：<类型名>（<一句判据：什么决定结构 + 画面语法>）
- 片方声称：<如"画面、音乐、音效均由 Claude 用代码生成"，原文照录，标出处时间点>

> 一句话：<这部片子讲什么、用什么方式讲>

## 一、内容理解
### 结构
<章节/段落划分，带时间>
### 时间线
| 时段 | 画面 | 屏幕文字（原文） |
### 声称 vs 证据
- 画面演示了的：…
- 只是写/说了的：…
- 看完仍不知道的：…

## 二、风格分析
### 画面基调
色板（底色 / 主色 / 强调色，尽量给 hex）、材质（粒子、印刷、手绘、写实、着色器…）、画幅
### 版式与字体
标签、标题、字幕的位置和字重，中英文字体气质，信息层级
### 运动与镜头
主要动效（聚散、描线、推拉、穿梭…）、缓动感觉、镜头语言
### 转场
逐类列出，带例子时间点
### 节奏
总时长、章节数、平均每个画面停留秒数（用 index.json 算）、快慢段落
### 声音
有无解说、配乐风格、音画关系。听不了声音时写"未分析"，不要编
### 技术路线推测
标为推断，逐条：推断实现 / 证据 / 把握（高·中·低）。证据要读原图局部（`ffmpeg -ss <秒> -i <mp4> -frames:v 1 -vf "crop=320:180:<x>:<y>,scale=1280:720:flags=neighbor"` 最近邻放大）：像素网格随推镜变粗 = 低分辨率画布放大；硬边像素外有平滑光晕 = 放大后再做后处理；方向性色块 = 油画类滤镜；独立叠压的笔触 = 粒子而非纯着色器。平台二次压缩会糊细节，压缩造不出的特征才算证据

## 三、复用指南
- **风格提示词**：一段可以直接交给创作流程的描述（一段话）
- **标志性元素**：让人一眼认出出处的东西（创作时保留还是替换，由每次问的相似度决定，不是禁用清单）
- **可迁移的手法**：换内容也能用的叙事/可视化手法，每条注明适合什么内容、不适合什么
- **做不到/慎用**：以本 skill 的工具看，哪些效果难复刻

## 四、代表帧
<6~10 张最能代表风格的帧，按时间，引用 frames/key/ 下的文件>
```

## 写作要求
- 屏幕文字、数字一律以原图为准；外部知识解释标"推断/考据"
- 风格描述要具体到能照着做："暖金粒子"比"很有质感"有用；给色值、字体名、缓动类型、时间点
- 声称和证据分三层写（上面模板），不把作者的说法当成画面事实

## 拆完之后：对照手法库
对照分析 md 的「技术路线推测」「可迁移的手法」和本 skill 现状（SKILL.md 原则 1、`docs/CRAFT.md` 手法库、`docs/TYPES.md` 类型表），在对话里给用户一张表：本片技法 → 已覆盖（指到具体工具/文档）/ 部分覆盖 / 未覆盖 + 建议。手法库还没有的手法列出来带适用条件，用户同意的加一行进 `docs/CRAFT.md`（出处写本片片名）。**缺口只汇报，要不要补由用户决定。**
