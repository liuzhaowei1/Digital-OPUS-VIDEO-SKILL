# 视频类型与创作判据

SKILL.md 给操作步骤；本文件给步骤背后的判据：视频怎么分类型、哪些事问用户、哪些由 Claude 提案、做的时候有哪些已知的坑。手法库在 `docs/CRAFT.md`，声音在 `docs/AUDIO.md`，画面素材在 `docs/ASSETS.md`。片名出处见 `docs/REFERENCES.md`。

## 方法观（统领下面所有条目）
**按内容设计；类型、手法、风格、工具都是起点，不是模板；体系是成长型的，现有的不是全集；用户每次反馈只对它针对的那类内容生效。**

- 不是每一类视频都适合同一种风格和做法。核心看做什么类型、讲什么内容，再挑手法
- 新收录一种类型或手法，不代表以后只能照它做
- 用户对某一部片子的意见（"这部节奏太快""这部和参考太像"）只针对那一部，不外推成通则。例：一部 21 秒、1~2 秒一换的短片被说"切换太快看不清"，不等于以后所有带字画面都要停 3 秒；宣传片、概念短片本来可以快
- 声音、配乐的方法论也在持续优化，`docs/AUDIO.md` 是创意参考，有更好的路子在创作中提出来

## 拆意图：哪些问、哪些提案
必问与默认的维度表在 SKILL.md Step 2。**创意概念、贯穿线、手法选择、叙事结构、转场不问用户**，由 Claude 在方案书里提案（意图开放时给 2~3 个方向各一段话）。用户要看的是创造性，不该被问"你想要什么母题"。

- **相似度每次问**：照搬风格换内容 / 借骨架做差异 / 只取一两个手法，三种都是正当需求
- **时长按信息量定**：一个概念约 8~15 秒讲清。30 秒讲不完 transformer，这不是节奏问题，是时长问题——信息量和时长不匹配时直接指出来
- **文字方案书缺画面感**：拍板环节别让用户读文字想象画面，给静帧或样片。短片的方案书照写（存档用），但确认靠图

## 视频类型
类型回答"什么决定结构"，给起点；「已见过的做法」是参照，同类型的新片可以完全不同。每部参考片归哪类，写在它自己分析 md 头部的 `- 类型：` 行（`docs/REFERENCE.md`），本表不列片子清单。

| 类型 | 判据（什么决定结构） | 已见过的做法（出处） | 常用栈 |
|---|---|---|---|
| **MV·图解** | 现成歌曲驱动；每句/每段歌词翻译成一个可计算对象、科学插图或技术隐喻 | 切点按歌词行吸附拍子，换画风或换中栏但锁色板/字体/骨架（《AGI概念MV》《被定义的我》《如果聊天窗口就是她的整个世界》） | 内置引擎（粒子、着色器重）；固定 HUD、DOM 为主的走 Remotion |
| **MV·动态排版** | 现成歌曲驱动；歌词文字本身是画面主体 | 一句拆多词、每词一个物体，词一出画面就换，持续运动而非快剪（《在我窗下》） | Remotion；3D 占比大改内置引擎；srt 可直接当时间轴 |
| **科普长片** | 内容驱动，无歌词无旁白，靠屏幕字推进；结构来自知识点 | 章节制或编号图版 + 首尾呼应，一屏一句结论，时长由信息量定（《从现在看过去·AI简史》《时·RELATIVITY》） | 内置引擎（粒子 + Layer2D 文字）；底乐可网格合成 |
| **概念短片** | 单一意象、≤1 分钟 | 同一主体反复变奏：极快蒙太奇 + 一两次尺度穿越 + 结尾揭示（《同一朵蘑菇云》） | 内置引擎（每种媒介一个着色器）；网格合成 BGM 最合适（短、切点密） |
| **叙事短片** | 剧情驱动；有角色、对白、起承转合 | 分幕制，画风随叙事段落切换（现实段 / 幻想段），对白段慢、幻想段一镜到底，首尾同场景回环（《Claude Dreaming》） | 混合：像素段 Canvas 2D 低分辨率放大 + UI 状态机；3D 段 three.js + 油画滤镜与景深；抽象段笔触粒子或着色器；真实肢体表演考虑 Blender |
| **思辨短片** | 一个哲学问题驱动结构（问→困境→转向→回答）；第一人称字幕独白，主角是抽象化身。与叙事短片的界线：无剧情冲突、无对白场面 | 材料即主题（万物由文字构成），困境段停住、高潮段长时间连续运动，字幕接力，首尾同一界面回环（《我从未见过太阳》） | 内置引擎（大规模文字实例 + bloom + 景深）+ 2D 字幕叠层 |
| **口播·讲解** | 旁白驱动，讲操作、工具、知识、资讯（与科普长片的界线：有旁白） | ① 固定版式：讲者小窗或吉祥物 + 章节目录 + 当前章节高亮 + 进度条 ② 竖屏资讯速览：贯穿物体连续演变 + 每段一个主色 + 逐字点亮字幕（《DevDay速览·三模型同题》Opus 栏）③ 写实实物演示：按知识种类分实物舞台，物体自己演物理过程，抽象阶梯落地理论（《拓扑优化》）④ 自我解剖：片子讲自己怎么做出来的，按制作流程分章，前面的镜头当后面讲解的例子，单色强调的暗底仪器版式 + 纸面、小票等道具，数值脊柱涨破到 NaN（《足够震撼》） | Remotion（DOM 排版、卡片、表格）；辉光、点阵用内置引擎；吉祥物按音量三档对嘴型；照片级写实考虑 Blender（未验证） |
| **口播·插画叙事** | 旁白驱动，讲人和关系、情绪、经历、观点；画面没有现成素材，要把话演出来 | 逐句一镜，动作卡在具体的字上，字幕缩成底部一行（纯字幕版被否掉后定的做法） | Remotion + 素材三选：纯 SVG 角色（`remotion/` 模板里的 `narration/` 角色与镜头工具）/ 生图整幅场景 + 代码镜头 / 生图角色抠图 + 场景图 |
| **片头·品牌短片** | 一个名字驱动结构：≤15 秒，种子元素生长或变形，最后落成 logo、片名卡或海报 + 标语；无旁白 | 一个元素一镜长成品牌（圆点 → 产品界面 → logo；一根线从种子画到整座城；一滴落下溅成字标），画风本身就是卖点（《popwise·扁平矢量》《NEON DRIVE·复古Synthwave》《drop·液态流动》等 12 部） | 按画风选：SVG + GSAP（矢量、描边、形变）；three.js（等轴、HUD、着色器）；Blender Cycles（软体、物理材质）；Canvas 2D（逐帧手绘、像素） |
| **产品宣传·UI动效** | 产品卖点驱动结构：痛点 → 转折提问（What if…）→ 功能演示 → 标语 + logo；30 秒~1 分钟，无旁白、靠屏幕字；画面是产品 UI 卡片的运动拼接。与片头·品牌短片的界线：讲多个功能场景，不是一个元素长成品牌 | 具名光标当用户主角，人物卡/步骤卡各占一种饱和纯色、同版式换底色连播，卡片带重运动模糊甩入，约 0.5 秒一换，字符乱码、半调溶解、点击涟漪放大成转场（《ClickUp AI·产品宣传》，工作室作品，未声称 AI 制作） | Remotion（DOM 卡片、打字、光标）；重运动模糊与景深要多帧采样或引擎后处理（推断，未做过） |
| **短视频包装** | 现成实拍素材驱动结构，代码只做包装层（花字、贴纸、描边、转场）；常为 9:16 竖屏 | 每段素材配一套花字，多层描边 + 弹跳 + 表情贴，放大情绪（《喵呜日记·综艺花字》） | DOM·SVG + 弹簧动画（Remotion）；素材由用户提供 |

- 分类先看**什么决定结构**（歌曲 / 旁白 / 内容 / 单一意象 / 剧情 / 一个问题 / 产品卖点 / 一个名字 / 实拍素材），再看画面语法；贯穿线、色板策略、可视化方式是跨类型的手法（`docs/CRAFT.md`），不用来分类
- 口播两类的界线：看旁白讲的是知识还是人；拿不准问用户。逐句插画只针对讲人和情绪的内容，不是所有旁白片都要这么做
- 新片子哪一类都不属于时停下问用户是否新增类型，定了再改本表；不自建
- 同一首歌的两种做法可作"相似度"样板：《被定义的我》与《如果聊天窗口就是她的整个世界》用的是同一首歌，前者数学对象 + 发光粒子，后者大模型生命周期 + 终端仪表盘

## 已知短板（写剧本、写方案书时必须考虑）
- ⚠️ **角色表演是代码做视频的短板**（叙事短片、任何有角色动作的片子）：剧本按"代码能演什么"写——角色为代码设计（情绪交给屏幕脸/符号脸，不交给肢体）、难动作拉远/遮挡/用速度糊过去、近景少动；照普通动画剧本写（如近景细腻起跑）基本达不到。实例：《Claude Dreaming》走路多远景背影、奔跑被草挡脚、特写只转头换脸。需要真实肢体表演时 Blender 骨骼 + IK 比纯代码直观（未验证）
- ⚠️ **动作质量和逐帧滤镜闪烁在静帧里看不出**：脚打滑、节奏僵、油画类滤镜相邻帧笔触跳动，要渲短片段连播才发现；Claude 只能看截帧序列，这类验收要请用户看片段

## 工具边界
- **工具按类型和内容选，不限代码**：先看类型表「常用栈」；内容适合纯代码的就纯代码，碰到代码短板再引入 Blender、ffmpeg 等可控工具，可混用。完整档的选型写进方案书由用户拍板
- **生图模型只出静态素材**（角色、场景、道具），动起来靠代码；做法与费用见 `docs/ASSETS.md`
- **不用视频生成模型**（Seedance 一类文生视频/图生视频）：那是另一条路，不在本 skill 的工具箱里

## 风格库之外的参考来源
- **awesome-opus5-5-videos**（GitHub `yihui-dev/awesome-opus5-5-videos`，Skillry 维护）：X 上 Opus 5.5 代码视频的原帖、提示词和原作/重做对照页。用 `scripts/skillry_ref.py` 取单条片段当一次性参考（产物在 `$OPUS_HOME/_refs/clips/<slug>/`）；反复要用的，按 `docs/REFERENCE.md` 拆进风格库
- ⚠️ **提示词≠风格**：画面常来自原作者没公开的设计稿（实例："Using the linked Figma frame… Match the design exactly"）；2026-10-08 该仓库 513 条里有 234 条标注作者只公开了部分提示词。复刻以原片画面为准。爆款提示词多是一句话加"go all out""exercise your own taste"，印证创意要由 Claude 发散提案
- 取片段：Skillry 托管的 `original.mp4` 就是页面那一段（≈720p）；X 原帖画质更高，但 yt-dlp 默认格式可能选中只有画面的 HLS 流，要用 `-f "b[protocol=https]/b"`，一帖多视频会拿错（按时长挑）——脚本已处理。`remake.mp4` 是 Skillry 重做版，不是原作
